## 一、核心概念（自己的话解释）

1. "变量 = 带名字的盒子"，那"类型"决定了盒子的什么？
   类型决定盒子**装什么**：整数（int）、小数（double）、真假（boolean）还是文字（String）；取值范围也被限定在类型里面（如 int 最大约 21 亿）。类型还决定了占多大内存、能做什么运算。

2. 为什么必须"先赋值再用"？把没赋值的变量打印出来会发生什么？
   赋值 = 往盒子里装东西。不赋值就用 → **编译报错**（`variable xxx might not have been initialized`），程序根本跑不起来。Java 宁可拦下你，也不让你打印一个"没定义的值"。

3. 自动类型转换和强制类型转换分别什么时候用？强转会丢什么？
   自动：小盒子转大盒子（int → double），不丢东西，什么都不用写。强制：大盒子转小盒子（double → int），**必须亲手写 `(int)`** 相当于签"免责声明"——不写的话编译直接报错。强转会丢小数部分（175.9 → 175，是截断不是四舍五入）。

4. 整数除法有什么陷阱？我（有没有）踩到？怎么修复的？
   **踩到了！** int 只管整数，两个整数相除结果也是整数（截断）。我的"132 事件"：温度转换器里写 `double f = 9 / 5 * c + 32;`，输入 100 得 **132**（应为 212）——因为 9÷5 按整数算得 1，公式变成 1×100+32。修复：让操作数带小数点 `9.0 / 5` → 得 212.0 ✅。教训：想要小数，除法里至少一个数带 `.0`；**装进 double 盒子也救不了**（先按整数算完才装箱）。

## 四、我今天写的代码（温度转换器最终版，标出修复的那一行）

```java
import java.util.Scanner;

public class Temp1 {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("请输入摄氏温度：");
        int c = sc.nextInt();
        double f = 9.0 / 5 * c + 32;   // ← 修复行：9.0 让除法按小数算
        System.out.println("华氏温度是：" + f);
        sc.close();
    }
}
```
